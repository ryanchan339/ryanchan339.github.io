Find the moment, not just the file

A filename cannot tell you where a scene appears, and a transcript misses moments that are only visible on screen. I built a local-first video search engine that accepts a natural-language query and returns playable timestamps from both visual and spoken content.

Two search paths, one result list

The visual pipeline samples frames and creates SigLIP embeddings. A separate pipeline transcribes speech with Whisper and embeds the text. Queries search both indexes using cosine similarity; standardized scores combine the results, and nearby duplicate hits are removed.

Engineering decisions

  • Spend work where the scene changes. Scene-based sampling reduced indexed frames by 42% on benchmark footage while retaining top-1 matches for the validated rabbit, butterfly, and apple queries.
  • Keep indexing out of the search flow. Background indexing lets the interface support a growing library, with both library-wide and per-video search.
  • Expose the ranking tradeoff. A control shifts emphasis between spoken and visual matches when one source is more useful.

Measure speed and quality separately

The larger SigLIP so400m configuration is the precision default; base-224 offers a faster indexing mode. The project benchmark measured 2.3 frames per second for so400m and 42 for base-224 on Apple Silicon. These are hardware-specific throughput measurements, not a universal speed claim.

The frame-reduction result comes from a small set of validated queries. It demonstrates useful savings on that footage, rather than proving equal retrieval quality for every video.
